## Why

Листинг сохранённых файлов живёт в `ConcurrentHashMap` внутри `FileStorageService`, а его единственная долговечная копия — JSON-сайдкары `{id}.meta.json` рядом с содержимым. При каждом старте сервис сканирует каталог хранения целиком, чтобы восстановить индекс.

У такого хранения три следствия. Индекс принадлежит процессу: второй экземпляр сервиса построит свой собственный, и они разойдутся. Метаданные нельзя ни отфильтровать, ни отсортировать, ни расширить полем — формат задан сайдкаром, который читается только целиком. И время старта растёт линейно с числом файлов.

`openspec/config.yaml` уже объявляет PostgreSQL базой проекта, но в `pom.xml` нет ни драйвера, ни миграций, ни каталога для них.

## What Changes

- Добавить зависимости `spring-boot-starter-data-jdbc`, `spring-boot-starter-flyway`, драйвер `org.postgresql:postgresql`, а для тестов `spring-boot-testcontainers` и `org.testcontainers:testcontainers-postgresql`.
- Завести каталог миграций `src/main/resources/db/migration` и миграцию `V1__create_stored_file.sql`, создающую таблицу `stored_file` (id, исходное имя, тип содержимого, размер, время создания).
- Сделать таблицу источником листинга: `StoredFileRepository` на Spring Data JDBC заменяет `ConcurrentHashMap`, сканирование каталога при старте уходит.
- **BREAKING**: сервис больше не пишет `{id}.meta.json`. Содержимое файлов остаётся на диске без изменений.
- Добавить одноразовый перенос: при старте сайдкары, чьих id ещё нет в базе, вставляются в таблицу, поэтому файлы, загруженные до этого изменения, не исчезают из листинга.
- Настроить подключение в `application.properties` и добавить `compose.yaml` с PostgreSQL для локального запуска.

## Non-Goals

- Перенос содержимого файлов в базу: байты остаются на диске, в таблице только метаданные.
- Любое изменение HTTP-контракта. `POST /api/files`, `GET /api/files` и `GET /api/files/{id}` отвечают тем же, чем и раньше.
- Удаление файлов, пагинация, поиск и фильтрация листинга — таблица делает их возможными, но эта задача их не вводит.
- Уборка «осиротевшего» содержимого — файлов на диске, для которых нет строки в таблице.
- Перевод `auth` на базу: токены остаются в памяти.

### Modified Capabilities

- `file-storage` — два новых требования: метаданные хранятся в PostgreSQL и применяются версионированные миграции; ранее сохранённые метаданные переносятся в базу. Существующие требования не меняются: наблюдаемое поведение API остаётся прежним.

## Impact

- `pom.xml`, `src/main/resources/application.properties`, новый `src/main/resources/db/migration/`, новый `compose.yaml` в корне.
- Новый подпакет `filestorage.repository` со `StoredFileRepository` и `StoredFileRow`; в `filestorage.service` `FileStorageService` теряет индекс и сканирование каталога, добавляется компонент переноса. `FileStorage`, `FileMetadata`, `FileStorageController` не меняются.
- Все `@SpringBootTest` начинают требовать DataSource, а значит Docker для Testcontainers — включая тесты `auth`, которые к базе отношения не имеют.
- Тестам нужна изоляция по данным: контекст пересоздаётся на класс, а контейнер общий, поэтому таблицу надо очищать между классами.
