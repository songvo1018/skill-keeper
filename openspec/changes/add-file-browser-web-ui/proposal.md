## Why

Сервис доступен только через HTTP API: чтобы увидеть свои файлы или заглянуть в содержимое, нужен `curl` с токеном. Нужен браузерный экран, где пользователь входит по паролю, видит список своих файлов и читает содержимое, не скачивая его. Список «своих» файлов невозможен сегодня: `stored_file` не хранит владельца, и `GET /api/files` отдаёт все файлы всем.

## What Changes

- Новая страница файлов: список метаданных, панель предпросмотра содержимого без скачивания, кнопка «Скачать», форма загрузки файла, кнопка «Выйти».
- Предпросмотр показывает текстовые типы (`text/*`, JSON, XML) как текст, `image/*` как изображение; для остальных — сообщение, что предпросмотр недоступен, и остаётся только скачивание.
- Новый экран логина: форма с именем и паролем, проверка полей до отправки, краткое сообщение об ошибке входа.
- Страница файлов недоступна без токена: при его отсутствии, истечении или отказе `401` браузер уходит на экран логина.
- **BREAKING** У сохранённого файла появляется владелец: загрузка записывает вошедшего пользователя, `GET /api/files` отдаёт только его файлы, `GET /api/files/{id}` на чужой файл отвечает `404 Not Found`. Клиенты, полагавшиеся на общий список, увидят только свои файлы.
- Файлы, сохранённые до этого изменения, остаются в базе без владельца и перестают появляться в списке и скачиваться: угадывать владельца задним числом нельзя, а отдать их первому вошедшему хуже, чем скрыть.

## Capabilities

### New Capabilities
- `web-ui`: браузерные страницы сервиса — экран логина с валидацией формы, страница списка файлов с предпросмотром, скачиванием, загрузкой и выходом, правила перехода на логин при отсутствующем или отвергнутом токене.

### Modified Capabilities
- `file-storage`: у файла появляется владелец; список отдаёт только файлы вошедшего пользователя, скачивание чужого файла неотличимо от несуществующего, файлы без владельца не отдаются.

## Non-Goals

- Регистрация с веб-страницы: аккаунт по-прежнему создаётся через `POST /api/auth/register`.
- Общий доступ к чужим файлам, папки, переименование и удаление файлов.
- Поиск, сортировка и постраничный вывод списка.
- Продление сессии и обновление токена: истёк — снова экран логина.
- Сборка фронтенда (npm, бандлер, фреймворк) и оформление сверх минимально читаемого.
- Смена схемы аутентификации: токен остаётся bearer-токеном в заголовке.

## Impact

- API: `POST /api/files` записывает владельца; `GET /api/files` фильтрует по владельцу; `GET /api/files/{id}` проверяет владельца.
- Код: `filestorage` (`controller`, `service`, `repository`, `model`), доступ к `AuthenticatedUser`.
- База: миграция `V3` — колонка владельца в `stored_file` и индекс под фильтрацию.
- Статика: страницы, стили и скрипты в `src/main/resources/static`, раздаются Spring Boot; под `/api/**` не попадают, поэтому перехватчик токена их не блокирует.
- Тесты: интеграционные проверки изоляции файлов между пользователями.
- Документация: таблица эндпоинтов и раздел про веб-страницы в `README.md`.
