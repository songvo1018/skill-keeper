## Purpose

Даёт пользователю браузерный доступ к сервису: вход по имени и паролю, список своих файлов, чтение содержимого прямо на странице, скачивание и загрузку — без командной строки и без ручной подстановки токена.

## ADDED Requirements

### Requirement: Экран входа
Система должна отдавать страницу входа с полями имени пользователя и пароля и кнопкой отправки. Страница должна проверять оба поля до отправки запроса и не отправлять запрос, пока проверка не пройдена. Пароль не должен попадать в адрес страницы, в заголовок вкладки и в сохраняемое состояние страницы.

#### Scenario: Успешный вход
- **WHEN** пользователь вводит имя и пароль зарегистрированной учётной записи и отправляет форму
- **THEN** страница получает токен от `POST /api/auth/login`, запоминает его на время сеанса и показывает страницу файлов

#### Scenario: Пустое поле
- **WHEN** пользователь отправляет форму, оставив имя или пароль пустым
- **THEN** страница показывает, какое поле не заполнено, и не отправляет запрос на вход

#### Scenario: Неверные учётные данные
- **WHEN** `POST /api/auth/login` отвечает `401 Unauthorized`
- **THEN** страница показывает краткое сообщение о том, что имя или пароль неверны, оставляет пользователя на экране входа и не сообщает, существует ли такое имя

#### Scenario: Запрос отклонён по формату
- **WHEN** `POST /api/auth/login` отвечает `400 Bad Request`, например из-за слишком длинного имени или пароля
- **THEN** страница показывает краткое сообщение об ошибке ввода, а не сообщение о неверных учётных данных

#### Scenario: Сервис недоступен
- **WHEN** запрос на вход не доходит до сервиса или отвечает ошибкой `5xx`
- **THEN** страница показывает краткое сообщение о том, что вход сейчас невозможен, и оставляет введённое имя пользователя в форме

#### Scenario: Повторная отправка формы
- **WHEN** запрос на вход уже отправлен и ответ ещё не получен
- **THEN** страница не отправляет второй такой же запрос, пока не получен ответ на первый

#### Scenario: Пароль нигде не остаётся
- **WHEN** попытка входа завершилась любым исходом
- **THEN** введённый пароль отсутствует в адресе страницы и не сохраняется между сеансами

### Requirement: Страница файлов требует токен
Система должна показывать содержимое страницы файлов только при наличии действующего токена. Если токена нет или сервис отвергает его, страница должна отправлять пользователя на экран входа, не показывая данные файлов.

#### Scenario: Токена нет
- **WHEN** пользователь открывает страницу файлов, не имея запомненного токена
- **THEN** страница переходит на экран входа и не запрашивает список файлов

#### Scenario: Токен отвергнут
- **WHEN** любой запрос страницы к `/api/files` или `/api/files/{id}` отвечает `401 Unauthorized`, например из-за истёкшего токена
- **THEN** страница забывает токен, переходит на экран входа и показывает краткое сообщение о том, что нужно войти снова

#### Scenario: Разметка страницы открыта, данные — нет
- **WHEN** страница файлов запрошена без токена
- **THEN** сервис отдаёт саму страницу, но она не содержит ни списка файлов, ни содержимого какого-либо файла

#### Scenario: Токен есть
- **WHEN** пользователь открывает страницу файлов с действующим токеном
- **THEN** страница запрашивает `GET /api/files` с заголовком `Authorization: Bearer <token>` и показывает результат

### Requirement: Список своих файлов на странице
Страница файлов должна показывать метаданные каждого файла, который сервис вернул вошедшему пользователю: исходное имя, тип содержимого и размер. Список должен отражать ответ `GET /api/files` и не показывать файлы, которых в нём нет.

#### Scenario: Файлы есть
- **WHEN** `GET /api/files` возвращает непустой список
- **THEN** страница показывает строку на каждый файл с его именем, типом содержимого и размером, а также действия «показать» и «скачать»

#### Scenario: Файлов нет
- **WHEN** `GET /api/files` возвращает пустой список
- **THEN** страница показывает пояснение, что файлов пока нет, вместо пустой таблицы

#### Scenario: Список не загрузился
- **WHEN** `GET /api/files` отвечает ошибкой, отличной от `401 Unauthorized`, или не доходит до сервиса
- **THEN** страница показывает краткое сообщение об ошибке и даёт повторить запрос, не отправляя пользователя на экран входа

#### Scenario: Имя файла показано как есть
- **WHEN** имя файла содержит символы разметки или непечатаемые символы
- **THEN** страница показывает его как текст, а не исполняет как разметку

### Requirement: Предпросмотр содержимого без скачивания
Страница файлов должна показывать содержимое выбранного файла в отдельной области, не сохраняя файл на диск пользователя. Содержимое должно запрашиваться у `GET /api/files/{id}` с токеном. Текстовые типы (`text/*`, `application/json`, типы XML) должны показываться как текст, `image/*` — как изображение.

#### Scenario: Текстовый файл
- **WHEN** пользователь выбирает «показать» у файла с текстовым типом содержимого
- **THEN** страница показывает его содержимое как текст с прокруткой, не сохраняя файл на диск

#### Scenario: Изображение
- **WHEN** пользователь выбирает «показать» у файла с типом `image/*`
- **THEN** страница показывает изображение в области предпросмотра, не сохраняя файл на диск

#### Scenario: Тип без предпросмотра
- **WHEN** пользователь выбирает «показать» у файла, тип которого не текстовый и не изображение
- **THEN** страница сообщает, что предпросмотр для этого типа недоступен, и оставляет доступной кнопку «Скачать»

#### Scenario: Слишком большой файл
- **WHEN** размер выбранного файла превышает предел, до которого страница показывает содержимое
- **THEN** страница сообщает, что файл слишком велик для предпросмотра, и не загружает его содержимое целиком, а кнопка «Скачать» остаётся доступной

#### Scenario: Содержимое не получено
- **WHEN** `GET /api/files/{id}` отвечает `404 Not Found` или иной ошибкой, отличной от `401 Unauthorized`
- **THEN** страница показывает краткое сообщение об ошибке в области предпросмотра и оставляет список файлов на месте

#### Scenario: Предпросмотр не выполняет содержимое файла
- **WHEN** содержимое файла является разметкой или скриптом
- **THEN** страница показывает его как данные и не исполняет в контексте страницы

#### Scenario: Смена выбранного файла
- **WHEN** пользователь выбирает «показать» у другого файла
- **THEN** область предпросмотра показывает содержимое последнего выбранного файла, а ресурсы предыдущего освобождаются

### Requirement: Скачивание файла со страницы
Каждый файл в списке должен иметь кнопку «Скачать», сохраняющую файл под его исходным именем. Запрос за содержимым должен нести токен, поэтому обычная ссылка на `/api/files/{id}` без токена не годится.

#### Scenario: Файл скачан
- **WHEN** пользователь нажимает «Скачать» у файла
- **THEN** страница запрашивает `GET /api/files/{id}` с заголовком `Authorization: Bearer <token>` и предлагает браузеру сохранить файл под исходным именем

#### Scenario: Скачивание не удалось
- **WHEN** запрос на скачивание отвечает ошибкой, отличной от `401 Unauthorized`
- **THEN** страница показывает краткое сообщение об ошибке и не сохраняет пустой файл

### Requirement: Загрузка файла со страницы
Страница файлов должна давать выбрать файл и загрузить его через `POST /api/files` с токеном, после чего список должен показывать загруженный файл.

#### Scenario: Файл загружен
- **WHEN** пользователь выбирает файл и подтверждает загрузку, а сервис отвечает `201 Created`
- **THEN** страница обновляет список, и загруженный файл появляется в нём

#### Scenario: Файл не выбран
- **WHEN** пользователь подтверждает загрузку, не выбрав файл
- **THEN** страница сообщает, что файл не выбран, и не отправляет запрос

#### Scenario: Сервис отклонил загрузку
- **WHEN** `POST /api/files` отвечает `400 Bad Request` или `413 Payload Too Large`
- **THEN** страница показывает краткое сообщение о причине отказа, а список файлов остаётся прежним

#### Scenario: Загрузка идёт
- **WHEN** запрос на загрузку отправлен и ответ ещё не получен
- **THEN** страница показывает, что загрузка идёт, и не отправляет второй такой же запрос

### Requirement: Выход
Страница файлов должна иметь кнопку «Выйти», после которой запомненный токен больше не используется, а пользователь оказывается на экране входа.

#### Scenario: Пользователь вышел
- **WHEN** пользователь нажимает «Выйти»
- **THEN** страница забывает токен, очищает список и область предпросмотра и переходит на экран входа

#### Scenario: Возврат назад после выхода
- **WHEN** после выхода пользователь возвращается к странице файлов средствами браузера
- **THEN** страница не показывает ни списка, ни содержимого файлов и отправляет пользователя на экран входа
