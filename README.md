# skills-keeper

HTTP-сервис на Spring Boot: регистрация пользователей, вход по паролю с выдачей bearer-токена и хранилище файлов. Метаданные лежат в PostgreSQL, содержимое файлов — на диске. К сервису прилагаются две веб-страницы: вход и список своих файлов с предпросмотром содержимого.

## Функциональность

| Метод  | Путь                 | Токен  | Что делает                                              |
|--------|----------------------|--------|---------------------------------------------------------|
| `POST` | `/api/auth/register` | не нужен | Регистрирует пользователя, отвечает `201` с id и именем |
| `POST` | `/api/auth/login`    | не нужен | Проверяет пароль, отвечает `200` с токеном              |
| `POST` | `/api/files`         | нужен  | Загружает файл (`multipart/form-data`, поле `file`), владельцем становится вошедший пользователь |
| `GET`  | `/api/files`         | нужен  | Отдаёт метаданные файлов вошедшего пользователя          |
| `GET`  | `/api/files/{id}`    | нужен  | Отдаёт содержимое файла, если он принадлежит вошедшему пользователю |

Всё под `/api/**`, кроме регистрации и входа, требует заголовок `Authorization: Bearer <токен>`. Проба готовности — `GET /actuator/health`, токена не требует.

Файл принадлежит тому, кто его загрузил: в списке видны только свои файлы, а запрос чужого файла отвечает `404 Not Found` — так же, как запрос несуществующего id, чтобы по ответу нельзя было узнать, есть ли такой файл. Имя владельца сравнивается без учёта регистра, как и при входе.

Файлы, сохранённые до появления владельцев, остались в базе с пустым `stored_file.owner_username`. Такой файл не показывается никому и не скачивается; чтобы вернуть его пользователю, владельца нужно проставить в базе вручную. По той же причине метаданные, перенесённые с диска при старте (`LegacyMetadataImporter`), сами по себе в списке не появляются.

Пароль хранится только хешем BCrypt и должен быть не короче восьми символов, содержать заглавную букву, строчную, цифру и специальный символ. Имя пользователя уникально без учёта регистра. Токен живёт 30 минут.

Пользователей в свежей базе нет: первый появляется только через регистрацию, она открыта для всех.

## Веб-страницы

| Путь          | Что это                                                                              |
|---------------|--------------------------------------------------------------------------------------|
| `/login.html` | Вход: форма с проверкой полей и коротким сообщением об ошибке                          |
| `/`           | Список своих файлов: предпросмотр содержимого, скачивание, загрузка, кнопка «Выйти»    |

Страницы — статика (`src/main/resources/static`), без сборки фронтенда. Токен они хранят в `sessionStorage` вкладки и подставляют в заголовок `Authorization` каждого запроса; когда токена нет или сервис его отверг, страница списка уходит на `/login.html`. Сама разметка отдаётся без токена, но данных о файлах в ней нет — всё подгружается запросом с токеном.

Предпросмотр показывает текстовые типы (`text/*`, JSON, XML) как текст, а `image/*` — как изображение; для остальных типов и для файлов больше 1 МБ остаётся кнопка «Скачать». Содержимое никогда не исполняется как часть страницы.

## Спецификация

Поведение описано в [openspec/specs](openspec/specs):

- [authentication](openspec/specs/authentication/spec.md) — регистрация, вход, защита эндпоинтов токеном, правила и хранение пароля

История изменений с обоснованиями решений — в [openspec/changes/archive](openspec/changes/archive).

## Развёртывание

Нужны JDK 25 и Docker.

Поднять базу:

```bash
docker compose up -d
```

Запустить приложение — Flyway применит миграции из `src/main/resources/db/migration` при старте:

```bash
./mvnw spring-boot:run
```

Сервис слушает `http://localhost:8080`. Собрать исполняемый jar:

```bash
./mvnw package
```

### Настройки

| Свойство / переменная                | По умолчанию                 | Назначение                              |
|--------------------------------------|------------------------------|-----------------------------------------|
| `SKILLS_KEEPER_DB_USERNAME`          | `skills_keeper`              | Пользователь PostgreSQL                 |
| `SKILLS_KEEPER_DB_PASSWORD`          | `skills_keeper`              | Пароль PostgreSQL                       |
| `spring.datasource.url`              | `…localhost:5432/skills_keeper` | Адрес базы                           |
| `app.file-storage.base-dir`          | `./data/files`               | Каталог с содержимым файлов             |
| `app.auth.password.bcrypt-strength`  | `10`                         | Стойкость BCrypt                        |
| `app.auth.token.time-to-live`        | `30m`                        | Срок жизни токена                       |

Умолчания учётных данных годятся только для локального `compose.yaml`. При развёртывании задайте `SKILLS_KEEPER_DB_USERNAME` и `SKILLS_KEEPER_DB_PASSWORD` переменными окружения, а каталог из `app.file-storage.base-dir` разместите на постоянном томе: в базе лежат только метаданные, и файл без содержимого на диске из списка пропадает.

## Тесты

```bash
./mvnw test
```

Тестам нужен работающий Docker: PostgreSQL поднимается через Testcontainers, по отдельной базе на каждый тестовый класс.
